# solx development

`solx` is a single native Rust binary for interactive Slurm jobs and scratch
renewal on Sol.

## Architecture

Preserve these contracts when changing user-visible behavior:

- JSON matches `json.dumps(obj, indent=2)`: two-space indentation, `\uXXXX`
  escapes for non-ASCII, and insertion-ordered keys.
- Results go to stdout. Diagnostics go to stderr as single plain lines without
  markup or color.
- Exit codes are 0 for success, 1 for runtime failure, and 2 for usage errors,
  missing config, or refused actions.
- Help, usage text, and completion scripts are generated by clap. Test their
  content, not exact wording.

**Modules.**

- `src/main.rs`: clap command tree, dispatch, and `config show` / `edit`.
- `src/side.rs`: Sol host detection through `hostname -a` and the kernel
  hostname.
- `src/slurm.rs`: `squeue`, `scancel`, `salloc`, and `srun` wrappers plus job ID
  resolution.
- `src/config.rs`: TOML config parsing and `[keep]` rules.
- `src/jobs.rs`: `job list`, `start`, `stop`, `jump`, and `time`.
- `src/keep.rs`: CSV planning, enumeration, and the touch pipeline.
- `src/init.rs`: starter config and walkthrough for `solx init`.
- `src/output.rs`: TTY detection, JSON output, and plain-text diagnostics.
- `src/completions.rs`: embedded static completion scripts.

**Design decisions.**

- **CLI parsing.** clap handles the command tree. Leading global flags (`--json`
  and eager `--version`) and the full `job start` tail are parsed manually
  because their behavior predates clap conventions. The first unconsumed bare
  token, including one after `--`, is the template; all remaining tokens pass to
  `salloc` in order.
- **`[keep]` matching.** `ignore::gitignore::Gitignore` is rooted at `/` and
  uses `matched_path_or_any_parents`. A bare path matches the directory and its
  descendants, and the last `!` negation wins. Matching vectors live in
  `config.rs` and `keep.rs`.
- **Enumeration.** `ignore::WalkBuilder` disables hidden-file filtering, ignore
  files, parent rules, and link following through `hidden(false)`,
  `ignore(false)`, `git_*(false)`, `parents(false)`, and `follow_links(false)`.
  The result matches `find DIR -type f` plus `find DIR -type d`: hidden entries
  are included and symlinks are neither touched nor followed. Directories are
  included because touching a file does not refresh its parent directory's
  timestamp.
- **CSV inputs.** Unified `sol-scratch-cleanup.csv` rows map `Action` to the
  existing stages; legacy warning files remain supported. Paths are deduplicated
  across sources in stage order. A flagged regular file is renewed directly.
  Keep-list excludes filter flagged rows, without pruning directory walks.
- **Touch.** `utimensat(AT_FDCWD, path, NULL, 0)` sets both timestamps to now
  and requires write permission rather than ownership. Explicit timestamps
  require ownership and fail with `EPERM` on writable collaborator-owned files
  (issue #47). Missing paths are skipped and never created, matching `touch -c`.
- **Counting.** `files_touched` and `dirs_touched` count entries with refreshed
  timestamps. `failures` counts failed operations: one per entry that could not
  be touched and one per directory that could not be walked. Counts are per
  entry, not per shard; a batch-wide failure must not collapse to one failure.
  Skipped roots are reported separately. Permission failures are grouped by UID
  with capped samples and directory emptiness, then owner names are resolved
  after workers finish. Failure counts and exit codes are unchanged by reporting.
- **Completions.** `assets/` contains static bash, zsh, and fish scripts
  embedded with `include_str!`. Update all three when the command surface
  changes; `tests/cli.rs` checks that each script emits successfully.

## Development workflow

Toolchain setup on Sol, including the rustup user install, `CARGO_TARGET_DIR`,
crates.io access, and glibc versus musl, is covered in
[`README.md` -> Toolchain on Sol](README.md#toolchain-on-sol).

**Local build.** Keep build artifacts off the NFS home directory:

```shell
export CARGO_TARGET_DIR=/tmp/solx-target
cargo build --release
cp "$CARGO_TARGET_DIR/release/solx" ~/.local/bin-test/solx
```

The native build links the host's glibc and runs on the machine where it was
built, including Sol.

**Checks.** Run the same format, lint, and test commands used by CI:

```shell
export CARGO_TARGET_DIR=/tmp/solx-target
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test
```

Unit tests live beside their modules and cover Slurm parsing, config, keep
matching and planning, and JSON formatting. `tests/cli.rs` drives the compiled
binary against the Slurm mocks in `tests/mocks/bin` with temporary HOME and XDG
directories, checking stdout, stderr, and exit codes.

**Portable build.** Releases and PR artifacts use the statically linked musl
target:

```shell
rustup target add x86_64-unknown-linux-musl    # one-time; no musl-gcc required
cargo build --release --target x86_64-unknown-linux-musl
```

The result is self-contained and has no libc-version dependency; `ldd` reports
it as statically linked. The CI `build` job uploads it as the
`solx-x86_64-linux-musl` artifact on every PR. Download it from the PR's
**Checks** page under **Artifacts** to test it on Sol without a toolchain:

```shell
chmod +x solx
./solx --version
```

`.github/workflows/ci.yml` runs the checks above on every push to `main` and
every PR, then builds and uploads the portable binary.
